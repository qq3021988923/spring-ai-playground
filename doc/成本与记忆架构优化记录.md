## 背景：一次对话的钱花在哪（改造前）

以 `/love/chat/sse/multi-query`（前端恋爱页实际使用的接口）一次完整对话为例：

| # | 环节 | 调用 | 是否每次必花 | 用户感知 |
|---|---|---|---|---|
| 1 | 润色 `rewriteIfNeeded` | 1× Flash | 仅问题 <15 字 | 同步（开头） |
| 2 | 变体扩展 `expand` | 1× Flash | 有 100 条缓存 | 同步 |
| 3 | 主回答 `stream` | ≥1× Flash | 必花（工具每轮再+1） | 核心 |
| 4 | 关键词生成 | 1× Flash | 必花（入库前） | 无感（后台） |
| — | embedding | 检索 2 + 入库 1 | 必花 | 无感（qwen，便宜） |

**记忆双写问题**：每轮问答同时进了 `.kryo`（短期原文）和 PgVector（长期原文），近期内容高度重复，检索时可能同一份喂两遍；PG 无限膨胀、垃圾轮次污染检索。

## 2. 砍关键词那次 Flash（对话入库）

**目的**：每次对话回答完成后，后台还会花 1 次 Flash 给"该轮问答"生成中文关键词再入库——纯后台、零感知、每轮必花，砍掉。

**改动**：`LoveAdvisorService.saveToVectorStore()` 的异步入库块

```java
// 以下两行已注释，需要恢复关键词入库时放开即可（代码与注入全部保留）：
// Document enriched = keywordEnricher.enrich(List.of(doc)).get(0); // LLM 生成关键词
// vectorStore.add(List.of(enriched));   // 带关键词入库
vectorStore.add(List.of(doc));    // 改为：原文直接入库
```

日志由 `【向量库存储，+关键字】` 改为 `【向量库存储】`；catch 语义改为兜"入库失败"。

**注意**：`KeywordEnricher` 类、注入、import **全部保留未删**；知识库初始化（`LoveDocumentLoader`，仅启动/重置时）仍在用它生成关键词，**不受影响**。

## 3. kryo 记忆窗口 100 → 30（恋爱独立配置）

**目的**：主回答每次把该用户最近 N 条历史原文全量塞进 Prompt——这是 **token 大头**。恋爱接口原先在构造器里写死 100，且不走 yml（yml 只对超级智能体生效），属于历史遗留双实例。

**改动**：

- `application-dev.yml` / `application-docker.yml` 新增：

```yaml
# 恋爱顾问（知心）对话记忆条数：独立于 manus
love:
  chat-memory:
    max-recent-messages: 30
```

- `LoveAdvisorService` 构造器：`new FileBasedChatMemory(fileDir, 100)` → 注入
  `@Value("${love.chat-memory.max-recent-messages:30}") int maxRecentMessages`

**效果**：`.kryo` 文件里全量历史照存，仅返回给 LLM 时截取最近 30 条 → 主回答 token 直降约 60~70%。

**配置分工**：

| 场景 | 配置键 | 值 |
|---|---|---|
| 恋爱顾问（知心） | `love.chat-memory.max-recent-messages` | 30 |
| 超级智能体（小羊） | `chat-memory.max-recent-messages` | 100 |

## 4. 长期库 123 改造（闲聊过滤 / 检索避重 / 档案卡）

**目的**：解决"kryo 与 PG 存同一份近期对话、重复喂 + PG 垃圾膨胀"；并把 PgVector 从"每轮原文镜像"逐步改造成"长期记忆精华库"，让用户**跨天回来能被记得**。

全部改动集中在 **`LoveAdvisorService.java`**。

### 4.1 记忆分层设计（改造后的目标架构）

| 存储 | 职责 | 内容 |
|---|---|---|
| `.kryo` | 短期工作记忆 | 最近 30 条原文，保证当场对话连贯 |
| PG `userId=system` | 知识库 | 恋爱知识文档（LoveDocumentLoader 加载） |
| PG `type=conversation` | 历史对话原文 | 超过 .kryo 窗口的更早对话，做相似度召回 |
| PG `type=user_profile` | **用户档案卡** | 有价值对话攒批提炼的"用户画像"，跨天回忆主力 |

### 4.2 第 1 步：闲聊轮次不进长期库

- 新增常量 `CHIT_CHAT_KEYWORDS`（你好/谢谢/在吗/哈哈…约 35 词）
- `saveToVectorStore()` 入库前过滤：问题去标点 ≤6 字且命中词表 → 跳过
- 方法 `isPureChitChat(question)`（零成本字符串判断，不调 LLM）
- 日志：`闲聊/问候轮次，跳过存入长期库：xxx`

**允许少量误伤**（如"你好漂亮"被当问候跳过入库）：只影响"不存库"，不影响当场聊天与 .kryo，可接受。

### 4.3 第 2 步：检索避重

- 新增常量 `RECENT_CONVERSATION_IGNORE_HOURS = 12`
- `buildMultiQueryRagAdvisor()`（前端实际使用的多 Query 检索）合并结果时，跳过"最近 12 小时内刚存"的 `type=conversation` 文档——近期内容 .kryo 已覆盖
- 方法 `isRecentConversationDoc(doc)`：只拦对话原文；知识库与档案卡不拦
- 日志扩展：`【多Query检索结果变体】：2 个，去重合并：X 条文档，跳过近期对话：N 条`

**边界**：仅作用于多 Query 检索路径；单 Query `/love/chat/sse`（前端未使用）保持原逻辑。

### 4.4 第 3 步：档案卡提炼（跨天记得用户）

- 新增常量 `PROFILE_FLUSH_THRESHOLD = 5`、提示词 `PROFILE_DISTILL_PROMPT`
- 新增字段 `pendingProfileRounds`（每用户内存缓冲）+ 注入 `flashChatClient`（Flash 轻量客户端，`@Qualifier("flashChatClient")`）
- `saveToVectorStore()` 中值得存库的轮次先进入攒批缓冲（`collectProfileRound`）
- 攒满 5 轮 → `distillProfileAsync` 后台调 1 次 Flash，浓缩成档案要点，存 `type=user_profile`（按 chatId 隔离）
- 日志：`【档案卡已沉淀】用户：love_user001 | 提炼 5 轮 → - 异地恋，女友在深圳 ...`

**成本**：每攒满 5 轮才 1 次 Flash + 1 次 embedding（摊薄），纯后台；失败不重试（避免反复烧钱）。服务重启时未攒满的缓冲会丢（代价极小）。

### 4.5 注释补齐

类头部新增架构总注释（记忆分层 + 三条规则）；`saveToVectorStore`、`isPureChitChat`、`collectProfileRound`、`distillProfileAsync`、`isRecentConversationDoc` 均补了"干什么/为什么"级注释；入库时间格式复用顶部常量 `CONV_TIME_FMT`。

## 6. 验证清单与日志观察点

重启应用后逐项验证：

1. 控制台不再出现 `【存储数据的关键词】`
2. 正常出现 `【向量库存储】用户：xxx | 问答已写入 PgVector`
3. 聊一句"在吗/谢谢" → 出现 `闲聊/问候轮次，跳过存入长期库`
4. 聊满 5 轮有价值对话 → 出现 `【档案卡已沉淀】...`
5. 多 Query 检索日志带 `跳过近期对话：N 条`
6. 短期记忆日志显示 `取最近30条`（原为 100）
7. 隔天/换话题问相关情况，能靠档案卡回忆

## 7. 调参旋钮与还原方法

| 想做什么 | 怎么改 |
|---|---|
| 恢复关键词入库 | 去掉 `saveToVectorStore` 中两行 `//` 注释 |
| 调恋爱记忆条数 | yml `love.chat-memory.max-recent-messages` |
| 调闲聊词表 | `LoveAdvisorService.CHIT_CHAT_KEYWORDS` |
| 调检索避重窗口 | `RECENT_CONVERSATION_IGNORE_HOURS`（12） |
| 调档案提炼频率 | `PROFILE_FLUSH_THRESHOLD`（5） |
| 关闭闲聊过滤 | 删 `saveToVectorStore` 中 `isPureChitChat` 判断 |
| 关闭档案提炼 | 删 `saveToVectorStore` 中 `collectProfileRound` 调用 |
| 退回 Pro 模型 | yml `model: deepseek-v4-flash` → `deepseek-v4-pro` |
